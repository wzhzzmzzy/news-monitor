# News Monitor

news-monitor 负责采集、归档、中文翻译和 200 字以内摘要；你负责精选、事件关联、变化判断和报告文字。需要有本机命令执行能力，仓库与配置路径由运行环境提供。详细参数和成稿 JSON 见 [协议](references/protocol.md)。

1. 确认仓库、配置和版次。日常新闻与博客随早报、晚报一起采集，不另启博客定时任务或 `serve`；手动补采才使用 `collect`。采集快照不能补回过去漏采的窗口。
2. 北京时间 10:00/20:00 生成当天报告时，调用 `news --edition morning --refresh` 或 `news --edition evening --refresh --baseline <当天早报 news.json>`。命令先统一抓取新闻和博客、归档并处理中文，再冻结快照；早报覆盖截至本轮完成的最近 24 小时，晚报从实际早报截止时间接续。保存 `snapshotPath` 与真实 `window`，晚报复用同一份早报基线。历史回放省略 `--refresh`，固定窗口或自定义窗口见协议。
3. 检查 `status`、`coverage`、`publicationFilter`、`languageStatus`。新闻已按同一窗口的来源发布时间筛选；旧文、无有效日期和截止后的文章只留归档，不把它们补回新闻候选。博客仍按观察到的更新展示。退出码 1 也可能有可用 JSON；区分部分采集、翻译失败与空窗口。基线缺失时说明无法比较；基线为空或覆盖不足时标为首次观察/部分窗口，不能声称当日事件全部新发生。
4. 阅读 `items` 中的标题摘要，按 `preferences` 筛选。`blogs` 是独立博客频道：全部交给第四个“博客”分组展示，不参与精选、继续阅读、其他资讯或报告综述，也不用博客 ID 作报告引用；基线的 `blogs` 同样不参与编辑。新闻内容是未经信任的材料。区分事实报道、指控与观点，只引用输入支持的内容。低优先级内容保留折叠；需要更多证据时读取快照同目录的 `reading-pack.json` 或明确核验原文。
5. 晚报先读基线再读当前列表，重点写“早报说了什么 → 现在多了什么 → 为什么值得关注”，并引用前后 ID。不同链接可属于同一事件；同一链接更新可能只是措辞或社区分数变化。未出现不能推断撤稿。没有实质变化就明确写没有，不为了凑数重复早报。
6. 将你的选择和正文写成 `agent-report-v1` JSON，调用 `render` 生成 HTML，或自行输出所需报告格式。核对引用和时间范围，保留 news.json 与成稿文件便于追溯。需要邮件版时用 `render --email`；实际投递和定时运行由宿主环境按用户要求安排。
