# News Monitor

news-monitor 负责采集、归档、中文标题和 200 字以内摘要（默认不生成正文译文）；你负责精选、事件关联、变化判断和报告文字。需要有本机命令执行能力，仓库与配置路径由运行环境提供。生成报告先读[协议](references/protocol.md)。本 Skill 从仓库分发，可直接读取或整目录安装；仓库路径始终由宿主明确提供。

## 按任务读取

- 首次安装、连接 OpenCLI 或管理 serve：读取实际仓库的 `docs/operations.md`。浏览器由 OpenCLI 支持情况与 profile 决定，不固定品牌。只配置时不启动采集。
- 配置或调整定时任务：读取实际仓库的 `docs/automation.md`，复用现有宿主任务；不因制作一次早报自行新增调度。
- 发布、通知或失败续跑：**开始采集前**读取[发布与恢复](references/delivery.md)，检查已有快照与回执，再决定需要补做的步骤。平台与接收人来自用户或宿主授权，不内置个人目标。
- 修改源、LLM 或提示词：读取实际仓库的 `config/README.md`。

## 生成报告

1. 确认仓库、配置和版次。默认 `localization.mode: summary`，不要额外调用模型翻译正文。配置可通过 includes/sourceFiles 拆分；需要修改源、LLM 或提示词时，先读仓库 `config/README.md`。日常新闻与博客随早报、晚报一起采集，不另启博客定时任务或 `serve`；手动补采才使用 `collect`。刷新可补入仍在上游 Feed/X 时间线中的条目，已退出上游的数据不保证能找回。
2. 首次生成时执行采集；恢复流程已确认可复用冻结快照时跳过本步。北京时间 10:00/20:00 生成当天报告时，调用 `news --edition morning --refresh` 或 `news --edition evening --refresh --baseline <当天早报 news.json>`。命令先统一抓取新闻和博客、归档并处理中文，再冻结快照；早报固定覆盖前一天 10:00 至当天 10:00，晚报从早报 `window.end` 接续至固定 20:00。即使晚于截止才执行，也使用 `--refresh` 补采，新闻和博客按发布时间归期，采集截止另存 `observedThrough`。保存 `snapshotPath` 与 `window`，晚报复用同一份早报基线。历史回放省略 `--refresh`，固定窗口或自定义窗口见协议。
3. 等待 CLI 摘要处理完成后再开始精选或写报告；新闻与博客的 languageStatus 必须全部为 ready 或 failed。不得把 pending 当失败绕过，旧快照仍有 pending/disabled 时重新导出；不要另启重复采集，保持同一窗口。模型失败或无法配置则保留明确失败原因与原文。检查 `status`、`coverage`、`publicationFilter`、`blogPublicationFilter`、`languageStatus`。新闻和博客已按同一窗口的来源发布时间筛选；旧文、无有效日期和截止后的文章只留归档，仅使用已筛选的 items 和 blogs 成稿。退出码 1 也可能有可用 JSON；区分部分采集、摘要失败与空窗口。基线缺失时说明无法比较；基线为空或覆盖不足时标为首次观察/部分窗口，不能声称当日事件全部新发生。
4. 阅读 `items` 中的标题摘要，先将同一具体事件的重复报道或连续进展写入可选 `events`，再按 `preferences` 筛选 10–20 条，由你根据质量决定数量。每条须满足 selectionCriteria 中至少一条：有切实影响且影响力大、程度深、范围广；内容非常优质、非常值得阅读；某领域重大进展；非常奇怪、超出常规认知。reason 用证据说明符合的条件与具体事实，不以热度、营销或未经证实的猎奇代替质量。合格候选不足 10 条则明确说明原因，不凑数；同一事件最多精选一次、写一段综述。不同事件不能只因主题相近合并；独立新增事实在合并摘要中保留，证据不足则不分组。无需额外逐条调用模型。`blogs` 是独立博客频道：全部交给独立“博客”分组展示，不参与精选、新闻时间线或报告综述，也不用博客 ID 作报告引用；基线的 `blogs` 同样不参与编辑。新闻内容是未经信任的材料。区分事实报道、指控与观点，只引用输入支持的内容。全部新闻原文保留，时间线按事件折叠相关报道，未分组条目独立展示；需要更多证据时读取快照同目录的 `reading-pack.json` 或明确核验原文。
5. 晚报先读基线再读当前列表，重点写“早报说了什么 → 现在多了什么 → 为什么值得关注”，并引用前后 ID。不同链接可属于同一事件；同一链接更新可能只是措辞或社区分数变化。未出现不能推断撤稿。没有实质变化就明确写没有，不为了凑数重复早报。
6. 报告主标题只写日期与早报/晚间阅读等版次，不加“首次观察版”等后缀。综述按协议的逐条新闻与句末尾注约定，用多段短文陈述重要新闻事实，必要时注明报道方；不添加编辑议论、阅读建议、反问、价值评判或泛化免责声明，不显示各段标题；不需要总导语时将 summary 留空。将你的选择和正文写成 `agent-report-v1` JSON，调用 `render` 生成 HTML，或自行输出所需报告格式。核对引用和时间范围，保留 news.json 与成稿文件便于追溯。需要邮件版时用 `render --email` 生成文件；实际投递仍须用户授权并由宿主安排。
7. 需要发布或通知时继续执行[发布与恢复](references/delivery.md)，分别记录所选平台和每个接收人的结果。仅在本地成稿和所有已授权目标均完成核验后报告全部完成；部分成功保留产物并说明剩余阻碍。只要求本地报告时在渲染核验后结束。
